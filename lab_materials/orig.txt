На основе анализа структурных данных и предполагаемой нагрузки был произведён расчёт аппаратных требований для системы заявок по подразделениям. Система рассчитана на одновременную работу до 100 сотрудников и 10 руководителей. Пусть сотрудник формирует 30 заявок по подразделениям в день, его рабочий день длится 8 часов. Количество заявок в сутки определяется по формуле 1.

На каждую заявку согласно диаграмме последовательности приходится 14 запросов к серверу. Вычислим RPS с учётом того, что каждый руководитель  генерирует ещё по одному RPS из-за механизма polling. RPS вычисляется по формуле 2.
       (2)

Цель
Необходимо разработать систему, включающую в себя вебсервис, вебприложение и нативное приложение, которая позволит сотрудникам формировать и отправлять заявки по подразделениям организации.
Назначение разработки
Необходимо разработать систему, которая будет автоматизировать работу с заявками по подразделениям и предоставлять актуальную информацию о них. Сотрудники смогут создавать заявки, выбирая подразделения, указывая их роли в заявке и связанные показатели (например, заработную плату) при заполнении формы. Руководитель смогут принять заявку к рассмотрению, утвердить её либо отклонить. Сотрудникам будет доступен список их заявок, включающий активные и обработанные. Гости системы имеют доступ к описанию подразделений и могут пройти регистрацию для последующей работы с заявками.

	•	Создание базы данных для хранения информации об устройствах и заявках на расчёт нагрузки (Postgres, gorm)
	•	Создание веб-сервиса со всей бизнес-логикой на Golang
	•	Добавление авторизации и swagger в веб-сервис с использованием Redis
	•	Разработка SPA на React для гостя

	•	Разработка интерфейса рабочего на React 
	•	Внедрение адаптивности и развертывание приложения
	•	Реализация нативного приложения на Tauri
	•	Развёртывание веб-приложения на GitHub Pages
	•	Подготовка всего набора документации (РПЗ, ТЗ и набор диаграмм)
